How to write an OpenEnv environment with senv: a kernel crate with the rules, a server crate with the OpenEnv shell. The kernel is an ordinary h5i-app kernel, so h5i app extract and h5i app prove work on it unchanged.

terminal
cargo run -p arith-env -- --ops 3

The two crates

The kernel crate has no web or database dependencies. It holds the snapshot, command, reply, and error types and a pure transition. Keep it in the Aeneas subset if you want h5i app extract to translate it to Lean.

The server crate implements h5i_app::Kernel for a marker type that calls the kernel, and senv::Environment for the shell:

MethodRequiredJob
metadatayesGET /metadata
principalyesThe principal every command runs as
resetyesSeed and episode id to a kernel command
stepyesThe step payload to a kernel command, or a validation error
stateyesThe read-only state command
observeyesCommitted snapshot and reply to an observation, reward, and done
render_stateyesThe state frame
refuseyesA kernel error to a wire error
schema, initialnoGET /schema; the snapshot before the first reset
tools, call_tool, tool_resultnoMCP tools on POST /mcp

Read the reward and done from what the kernel committed. If observe computed them, a proof about the kernel would not cover the reward the agent sees.

Serve

senv::run(env, senv::ServeArgs::from_env_and_args()) parses these flags and serves until Ctrl-C. A binary with its own flags flattens ServeArgs into its clap parser.

FlagEnvironmentDefault
--bindSENV_BIND127.0.0.1:8000
--max-sessionsMAX_CONCURRENT_ENVS8
--max-message-bytes16777216
--idle-timeout-secs120, or 0 to keep unattached sessions

GET /health returns {"status":"healthy"}. GET /metadata and GET /schema come from the environment. POST /mcp creates sessions and serves tools. GET /ws carries reset, step, and state. For tests, Server::spawn("127.0.0.1:0") serves on a free port in the background.

Python

Check out OpenEnv at 58d0344011fe961342706c90288f7e842b15b1c9. Install scripts/echo-client-requirements.txt from this repository into a Python 3.10+ virtualenv. Point PYTHONPATH at OpenEnv/src and OpenEnv/envs. With cargo run -p echo-env listening:

python
from echo_env import CallToolAction, EchoEnv

with EchoEnv(base_url="http://127.0.0.1:8000").sync() as env:
env.reset()
step = env.step(CallToolAction(tool_name="echo_message", arguments={"message": "Hello!"}))
assert step.observation.result["data"] == "Hello!"
assert env.state().step_count == 1

scripts/echo_compat.sh, scripts/wordle_compat.sh, and scripts/arith_compat.sh build each example, wait for /health, and run the unmodified client. Set OPENENV_SRC to the checkout.

Limits

  • Disconnecting the WebSocket destroys the session. A later session/close may report an unknown id. The official client ignores that.
  • Messages stop at 16 MiB unless you raise --max-message-bytes. The Python client's default is 100 MB.
  • There is no HTTP /reset, /step, or /state, no CORS, and no web UI. Sessions always run on MemoryEngine.
  • A proof about the kernel does not cover socket isolation or rendering. Isolation is a separate engine per session, checked by tests.

The message shapes are in PROTOCOL.md. The architecture is in DESIGN.md.
