RL environments as h5i apps

Write the rules as an h5i-app kernel: a pure function that decides every reward and every done. Prove properties of it in Lean 4 with h5i's tooling. senv serves it on the OpenEnv wire, so the unmodified Python clients train against it.

How it fits

The kernel decides. The shell renders.

An environment is a kernel crate and a server crate, the same layout as any h5i app.

Kernel
An ordinary h5i_app::Kernel. transition takes the snapshot and a command and returns the next snapshot and a reply. Rewards and termination live here, where h5i app extract and h5i app prove can reach them.
Environment
Implement senv::Environment: turn an OpenEnv reset or step into a command, and render the committed snapshot as an observation. Optional MCP tools go on POST /mcp.
One engine per session
Each OpenEnv session runs on its own MemoryEngine, so a property of the kernel holds per session. Disconnect drops the engine.
In-process too
senv::Session drives the same kernel and rendering without a socket, for tests and for Rust rollouts.
#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    senv::run(MyEnv::default(), senv::ServeArgs::from_env_and_args()).await
}
Examples

Three environments, checked against the official clients.

PASS official EchoEnv reset/step/state, isolation, reconnect
PASS official TextArenaEnv Wordle reset/step/state, feedback, win, invalid, isolation
PASS official TextArenaEnv Arith-v0 reset/step/state, score, hidden value, isolation

examples/echo is the OpenEnv Echo MCP environment. examples/wordle is Wordle-v0 with a Lean 4 model of its kernel. examples/arith is a multi-turn calculator task whose answer never appears in the observation or in state(). The wire subset and the differences from upstream are in the protocol note.
